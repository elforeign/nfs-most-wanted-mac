# X360 renderer features, widescreen, antialiasing, display changes (part 3 of 7)

Part of the runtime documentation; the index and switch lookup hint are in `runtime/README.md`.

Shared pre-treatment geometry (`shared_depth.m`, no switch): graph nodes declaring normals or min/max request a current-frame set before graph dispatch, then read it from their frame. Other consumers can use `shared_depth_request` and `shared_depth_get`. Contact shadows requests only while On; a registered spatial consumer still receives its set with AO Off. The set borrows the existing full-resolution resolved depth and creates half-resolution float32 view-space normals/linear depth plus a linear-depth min/max chain through 1×1. Every source pixel contributes to the bounds, including odd edges; sky contributes the far plane. Normals retain the original AO sample positions and arithmetic, with GPU equality checked against the pinned original four-tap shader through the shipping 1×/2×/4×/8× resolve and RGB-only SDR/HDR multiply encoders in SP and both split views (AO and SDR tolerance 0.0001; stored HDR within one half-float code step, with AO checked before quantization). SP and each split player own separate storage and bounded atlas coordinates; mirrors get none. Contents expire every frame, so camera cuts cannot reuse spatial data, including cuts within the same camera object. Resize, MSAA, HDR/SDR, camera/player identity and post-generation/mode changes retire storage and advance its epoch. Player identity is the live IPlayer object selected by its logical slot in the local-player vector, including single-player; replacing that object with the same camera still advances the epoch. The Metal fixture drives the production bridge and graph-dispatch hook from guest-memory camera/player data and live MSAA/HDR inputs, with independently rejected broken gatherers. Across 108 cases, graph output matches pre-graph stored colour/alpha exactly. Normals-only and min/max-only consumers also run with AO Off in SP/P0/P1. No consumer means no allocation or encoding, and retained textures for that view are released. Storage is approximately 55.30 MB per 3840×2160 view, excluding the borrowed resolve and existing AO targets. `BOOT_DIAG_GPUPASS=1` reports `shared depth normals + minmax L0` and `shared depth minmax L1` through the root; sum these labels for the set's GPU work. Later passes must use its frame, rectangle and bounds contract; it carries no temporal history.
