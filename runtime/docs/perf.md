# Frame rate, timing and CPU cost

Part of the runtime documentation; the index and switch lookup hint are in `runtime/README.md`.

## Frame rate and timing (`pacing.c`)

Session setup and display-change notes include the screen's current, potential and reference EDR headroom (sampled every 5 s). These are AppKit colour-component limits, not an HDMI HDR signal-mode flag; `HDR transport=unknown` is explicit because the public CoreGraphics display API exposes no such getter. The port continues to output SDR sRGB even when the screen has EDR headroom.

The game simulates in fixed ticks (`Scheduler::Run`, 00642E60; 1/60 s in the original) and renders once per main-loop pass. Its own limiter alternates ~16/~4 ms frames on a fast CPU, and the short ones run no tick, so they repeat the previous picture (pixel-identical in `BOOT_DIAG_SEQ` captures). `NFS_FRAMEPACE=game` restores the original: 60 Hz ticks, the game's limiter (~95-100 fps counted, ~40 % repeated frames) and its real-time counter. `BOOT_KEYS seq:` scripts count `wait:`/`idle:` in 1/60 s of real time, so they behave the same at any frame rate.
- **Loading waits poll every 1 ms, not 8-10** (`NFS_SLEEP_IOWAKE`, default on, 2026-10-25                                                         ): the game's loading waits poll with `THREAD_yield(8)` (alertable `SleepEx`), one loading step per poll, so `TrackStreamer::WaitForCurrentLoadingToComplete` (00730390; from `BlockUntilLoadingComplete` 007317A0, `MakeSpaceInPool` 00730BF0: a NIS or HUD load after a career event warp) froze one frame for 17 polls x 10 ms (the session's 169 ms 'sleep' frames). On the game thread that sleep now ends when a thread that read a file lets go of the GIL (or at once if one did since the last poll), else after 1 ms. `BOOT_DIAG_WARP=20:-441.7,94.9,2419.2:block` (a warp to the session's grid and a block in one frame, BOOT_DIAG) measured 472.8 ms with `NFS_SLEEP_IOWAKE=0`, 67.8 ms on; without `:block` it calls `Game_WarpPlayerToTrigger` (00611570; frames keep presenting there). BOOT_DIAG logs every game-thread Sleep (`sleep:` in events.log) with its callers.

## CPU cost of a frame

`NFS_LUM_NOWAIT=1` opts single-player exposure into completed-only luminance readback (default `0`, previous-frame wait). Startup and each resource epoch retain the previous-frame wait until a scene measurement (luminance at least 0.002, matching the adaptation's black-screen threshold) has been consumed. Black loading readbacks cannot release that wait: the first scene must initialize exposure on the same frame as Off. Thereafter it consumes the newest completed slot, retains the previous measurement if none completed, and never overwrites pending storage or waits for a free slot. Three slots cover Present's one previous frame plus the current frame and a spare. With `BOOT_DIAG`, `lumread.tsv` records frame/sample serials, measured luminance (`-1` holds the previous value), applied exposure, readback wait ns and writable-slot availability; `postfx.log` records the adaptation each frame. Split view always uses completed-only readback.

Race 11.1.1 at level 4, 1280x720, diagnostics on: the game thread is busy ~3 ms per frame (`stats.log` `busy`), down from ~13 ms. What changed (git log `8f5ceab`, `c022d63`): Present no longer waits for the GPU (one frame in flight, resources rewritten by the game while a pending frame reads them are renamed); draws build no Metal descriptors and skip bindings the encoder already has; float constants upload only the registers a shader reads, only when changed; `CommitChanges` applies only what changed (D3DX semantics); the game's 100 Hz TIMER thread no longer spins (absolute waitable-timer times); guest threads only take the GIL when their wait is satisfied; the recompiled code keeps registers in host registers across guest memory accesses (`recomp/README.md`).

`NFS_RENDER_THREAD=1` (`render_thread.m`                                                              ): Metal encoding leaves the game thread. Command buffers become recorders (encoder calls appended as compact ops, `set*Bytes` copied, objects retained once per buffer); one render thread replays them in commit order into real command buffers and commits; the present queue's drawable work waits for the frame's real commit. Translation, uploads and object creation stay on the game thread; the bound is the existing one-frame-in-flight wait. With `BOOT_DIAG` the `render thread:` event gives buffers per second, recorder commit -> real commit (mean/max) and replay ms. Default `1` since 2026-10-26 (solo A/B a,b,b,a at race 1.2.1 4K AA 2x, 3,550 draws: game thread busy p50 7.36 -> 6.21 ms, p99 8.39 -> 7.27; replay adds 0.81 ms between the game's commit and the GPU commit); `0` = the direct encoder calls.

## Shader compiles

Shader source compilation (`render.m`, 2026-10-28): device creation queues the embedded effect shaders, their material variants and common fixed-function variants on four worker threads, then joins them **before the first scene frame**. Identical MSL shares one in-flight library; unused binding options are canonicalized without changing generated source. The tradeoff is more work during initial device loading. Later misses always compile on worker threads, including FE/loading: unexpected base misses may wait for that shader alone, with **1 ms total per frame**, then defer if still pending. Optional variants retain the compiled base draw, including Carbon lamps. `NFS_ASYNC_SHADERS=0` no longer enables synchronous source compilation. Pipeline prewarm is separately opt-in below; grass PSOs keep their existing asynchronous/PC-fallback path (`NFS_TEST_GRASS_SYNC=1` is the synchronous control). No binary archive was added.

`NFS_PSO_PREWARM=1` (default `0`) builds EDR post libraries/pipelines (both lamp variants), shared post setup, AO depth and AO smoke helpers during device loading. Once effect shaders are ready, the same four queues replay 93 descriptor recipes and join before the first scene frame. Recorded from one race and one free-roam entry, recipes contain shader identities, Metal vertex layouts, attachment formats, blend/write state, alpha-to-coverage and sample counts; scene recipes follow configured AA. Ordinary draws, AO replay and material helpers share the cache. Unseen descriptors retain existing creation/fallback behavior. No binary archive or disk pipeline cache.

With `BOOT_DIAG`, `pipeline_frame: builds=N known=N total=N known_total=N` counts frame-path creations each second: material/static passes, clears, environment filtering and presentation copies/overlay. Background grass is excluded. `known` counts catalogue descriptors and prewarmed EDR/AO helpers; other `builds` identify unseen work. `pipeline_prewarm: loading_ms` measures initial shader/pipeline loading; `ready` reports cache publication. Missing shaders/failed builds are logged. `pipeline_cache_test.py --diag DIR` rejects listed frame-path builds, including older descriptor captures. Counter clocks and descriptor recording are disabled without diagnostics.
