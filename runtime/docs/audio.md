- `NFS_AUDIO_LIMITER=on|off` (default `on`; F10 Audio > Peak limiter, live): linked six-channel look-ahead peak limiter on the game mix (-1 dBFS, <= 2 ms look-ahead = 88 frames at 44.1 kHz, 150 ms release), hooked at Snd's float->int16 converter `00825957` (`audio_limiter.c`) because the guest hard-clips there, before the host clamp; the host adds only an instant linked bound after resampling. Movies bypass it (`movies.c`); Off is byte-identical to before. perf.tsv/stats `limit_samples` counts limited samples next to `clip`; with `BOOT_DIAG`, stats.log adds `limit_min_gain` immediately after `limit_samples` (minimum linked linear gain in that reader's window; 1 = unity, 0.5 ≈ -6 dB). Gain tracking is compiled out of the non-diagnostic processing path. Measured limit count (X360 mix pursuit: clip 0, 2.15 M limited samples = ~8 s of 150 s). Offline proof: `host/audio/build.sh` (limitertest, limiter_guest_test, each with a broken variant).                                                                           
- PCM/Stereo queue latency is at least two output-device I/O periods plus its output safety offset, rounded up after conversion from the nominal device rate to the stream rate. The floor applies on initial open, output reuse, device changes and primary-format rate changes, including an explicitly shorter `NFS_AUDIO_LATENCY`; larger explicit targets remain in effect. If the period cannot be read, the existing 1024-frame PCM default remains. Encoded defaults are unchanged (DD/DD+ 3072, TrueHD 4096). Offline fake-device proof: `host/audio/build.sh` exercises 4096-frame periods at 48 kHz with 128-frame safety offset and a 44.1 kHz stream (7644-frame target), with diagnostics on/off and a broken 1024-frame target.
- `NFS_AUDIO_LAUNCH_REOPEN=0|1` (default `1`): once per process, request one output/encoder close and background reopen, through the Audio menu's path, starting 1.5 s after the first successful bitstream open (TrueHD/MAT, Dolby Digital or DD+). This is a workaround for silence after a quick quit/relaunch while the HDMI/eARC receiver may still be relocking; the port cannot read its lock. The delay exceeds the 0.5 s host health window and the recorded ~1 s startup, but is a starting value for the physical TV/receiver check, not a measured receiver settle time. Guest cursor polls trigger it only in the unpaused startup front end; a paused/loading poll skips it, and a first poll after 5 s expires it. PCM/null outputs are unchanged. Startup device recreation carries the timer across healthy parked-output reuse; later loads cannot rearm it. Set `0` to disable. One always-on `audio: launch reopen done|skipped:<reason> after <ms> ms, format <fmt>` line in `NFSMW.log` records the result; `done` measures completion (including the background open), not just the 1.5 s request delay. A failed open uses the existing output-loss recovery and never rearms the launch action. Reopening may briefly interrupt sound; whether it fixes the physical link remains unverified. The fake TV should see two sequential TrueHD outputs when enabled, one when disabled, with all ordinary device recreations still reusing the current stream.
- `NFS_AUDIO_LATENCY=<frames>` (user-facing tuning): sets the output queue target; default automatic: TrueHD 4096, DD/DD+ 3072, PCM/stereo/null 1024 frames; positive values override it.
- `NFS_AUDIO_RATE=<Hz>` (user-facing tuning): fixes the mix rate; default 0/automatic follows the game for PCM/stereo (initially 48000); Dolby outputs require 48000 Hz.
- `NFS_AUDIO_TEST_DROP=<seconds>[/<failed-opens>],...` (test-only; default no drops): simulates output loss and failed reopen attempts; `0/N` fails N opens at creation.
- `NFS_DSOUND_LOG=1` (test-only; default unset/off): enables verbose host DirectSound logging; any set value enables it.

**Engine sound (`posaudio.c`, 2026-10-25; default Realistic):** F10 Audio > "Engine sound" / `NFS_ENGINE_SOUND=retail|realistic` (live). Retail: the player engine is one full-gain point that `SFXCTL_3DRearPos::UpdateParams` 004E5A80 puts 2 m behind the car centre in the hood/bumper cameras for every car, so 5.1 plays it from SL+SR only (chase camera: C only). Realistic changes only the pan of the player's own Ginsu engine voice (CARSFX_GinsuEngine 004EE3E0 whose CSTATE, +0x14, is the Rear Car Pos controller's): the engine sits at the car's real layout (table `kEngineCars`, keyed by the pvehicle collection key at `EAX_CarState+0x200`, Collection+0x20 = Attrib hash of the name; unknown cars keep the 2 m-behind point) relative to the camera (2D position/facing at 009144A0/009144C0 per view, the same inputs as `SetCameraAngle` 004B5D70), spread over an arc by its apparent size, plus a 10 % diffuse share, scaled to the retail gains' power. The controller output the mix map reads stays retail (its level curves depend on angle and distance), so loudness is unchanged. Measured hood camera: 0.2-0.6 m ahead of the car centre. `BOOT_DIAG` `posaudio:` lines gain `player_engine[realistic= key= layout= az= dist= cam_along= retail_check= updates= spread=] shares retail=C,FR,SR,SL,FL realistic=... power_db=` (`retail_check`: the retail source's azimuth recomputed from those inputs minus the one the game wrote, 0 +-14 of 65536 in races). Offline test: `runtime/posaudio_test.py`. **Player's tyre/road/body voices:** Realistic also moves the bank voices on the Rear Car Pos controller (the same 2 m-behind point) to the four wheels, matched by the angle word that controller gave the mix map (`rear` in `posaudio.c`, `rear_voice`): quarter power per wheel (track 1.56 m, wheelbase 2.7 m), each spread by apparent size, power unchanged. BOOT_DIAG: `soundstage:` gains `rear[seen= wheels=]` and a `rearpos[...]` speaker-use class; `soundstage-ctl:` one line per 3D controller class (vtable 008974F8 Col, 00897540 Scrape, 00897588 Car, 00898420 Left Wheel, 00898468 Right Wheel, 008984B0/008984F8 Right/Left Wind, 00898540 Fountain, 00898588 Woosh, 008985D0 Rear; view 0 another car, 1 the player's car in chase, 2 in hood/bumper) with where its source sits relative to the player's car and the speaker shares of the bank voices that carry its angle word; `soundstage-vrec:` / `soundstage-slots:` (every 30 s) voice-record words and voice slots per controller class.

**Soundstage (same Engine sound switch):** Realistic also spreads AI racers' and cops' engines (CARSFX_GinsuEngine / CARSFX_AEMSEngine), traffic engines and cop sirens. How the game pans a source: the 3D controller (`SFXCTL_3DObjPos::GenerateSinglePlayerMix` 004B5E50, the player's `SFXCTL_3DRearPos` 004E5A80) writes a camera-relative azimuth and distance, the mix map turns them into the object's input words (`**(obj+0x10) & 0xFFFF` is the angle), the object hands the angle to Snd: the Ginsu engines synchronously (`_SND3dpos` in 004EE820/004EEA00), traffic/siren/AEMS engines through a Csis member block that the AEMS script reads later on the Snd thread (`SNDAEMSI_bankazimuth` 0081A0AC, FUN_0081F207 caller 0081A0D1; music/NIS streams `_SNDSTRM_setazimuth` 0081CF56), and `FUN_0081FE64` turns the angle into five gains. Realistic changes only that last step for these voices: the gains become the panner's average over the arc the car subtends at its distance (engine at its layout offset, siren on the roof; power of the game's gains kept), and the asynchronous voices are matched to their source by the angle word (a match whose angle is further from the source's recomputed azimuth than 3 deg + 1 m of travel is left retail). Retail, mix maps, levels, music, ambience and every other sound are untouched. BOOT_DIAG: `soundstage:` per second (registered/matched voices, spread/skipped/rejected, the azimuth gap, and per class player/ai/cop/traffic/siren/bank/stream/other the mean speaker shares and how many updates reach C / SL+SR) and `soundstage-callers:` (the pan call sites outside the source hooks). Offline test: `runtime/posaudio_test.py` (Retail byte-identical for AI/cop/traffic/siren, async matching, nine broken variants fail).
**Audio-loop watchdog (`dsound.c`, always on):** a looping stream (Play with DSBPLAY_LOOPING, >= 16 KB, written at least 4 times) whose play cursor travels one full buffer while no Lock/Unlock write happened for over 1 s and the game isn't paused writes `audio_loop_N.txt` into the session folder (stream state, Snd thread and every guest thread's wait, the last 32 buffer operations) plus one `audio: loop watchdog` line (NFSMW.log, session.txt); at most 3 a run. Checked once per 250 ms from the per-frame pass (so a stuck Snd thread cannot silence it); per buffer operation it adds one tick and a counter. `NFS_TEST_AUDIOLOOP=<s>` (test only) refuses Lock/Unlock of the watched stream from <s> seconds on, which makes the cursor cycle stale data. BOOT_DIAG: `dsaudio watchdog checks= fired= max_quiet_ms=` and one state line per watched stream.
**Extra EA Trax** is owner-only and absent from the public build (`extratrax_public.c` stands in; its code, catalog and F10 row are not compiled).

**Positional audio (`posaudio.c`, 2026-10-23):** the 47 reads of `AudioSettings+24` that pick positional vs zero azimuth (list in `recomp/recomp.py` `POSITIONAL_MODE_READS`) return 1 whatever the career saved; guest memory and the save are never written (hooks.txt can't do it: the reads are mid-function). F10 Audio "Speaker layout" / `NFS_SPEAKER_LAYOUT=game|itu` (default game: the original table, byte-identical; itu: fronts ±30°, surrounds ±110°, interpolated gains, fixed music source defaults remapped). BOOT_DIAG writes a `posaudio:` line per second (settings+24 loaded/used, per active engine/traffic/siren/heli source azimuth and the five gains). Test: `runtime/posaudio_test.py`.
