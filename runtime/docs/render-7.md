## Post groundwork: atmosphere tables and the pre-treatment pass graph

Shared pre-treatment groundwork (`atmosphere.{h,m}`, `pre_treatment.{h,m}`; no switch): atmosphere tables are built on demand only when normalized sun, authored fog RGB or distance changes. The game supplies its live sun and evaluated weather-fog record; split consumers supply their own record. Cited sea-level Rayleigh/Mie coefficients use inverse metres, HG g=0.8 and homogeneous single-scatter Beer-Lambert transport. The authored fog start sets the 64-distance LUT range, not visibility or density; samples clamp to it. Only the radial transport integral is tabulated; Rayleigh and HG phases are evaluated analytically at the actual sun/view cosine, including the forward peak. Across 12,004 angles the analytic reference error is at most 0.000168%; the former 65-angle interpolation reached 31.2382%. No current pass requests/uploads these CPU tables. Later effects must account for game fog; particle/smoke optics remain separate. The graph precedes X360 treatment and declares scene/shared depth/normals/min-max, intermediate ownership, colour outputs, dependencies and future history inputs. Only the original AO/smoke node is registered; its RGB-only in-place encoder preserves alpha and player-local sampling. AO requests its optional geometry only while On. Other nodes declaring normals or min/max automatically request the current view's set before dispatch, even with AO Off; no separate caller request is needed. Future haze/shafts/heat/TAA register on the render thread, with distinct outputs for scene sampling. Mirrors are excluded; empty dispatch is one integer test with no allocation, encoding or binding. Offline tests reject wrong order, swapped coefficients, coarse phase interpolation, missing spatial-input requests and omitted production graph dispatch. They retain split-post snapshots and drive the extracted production dispatch hook for 108 exact AO/smoke comparisons: SP and both split players, RGBA/BGRA SDR and RGBA16F HDR, and 1×/2×/4×/8× MSAA. All stored codes, including alpha, match the pinned pre-graph main encoders. Split AO stays On; full/half smoke remains SP-only, and split cases verify that no smoke layer is applied or finished. The 3840×2160 RGBA16F+Depth32F fixture (private targets, 8 warmup pairs, median of 41 alternating GPU timestamps) measured **1.808083 ms separate / 0.535375 ms fused**, saving **1.272708 ms**: **fuse** meets the ≥0.1 ms rule. All stored half codes match, retaining rounding after each stage. This is placeholder work; actual effects need their own proof before fusion ships. Logs: `.metal-cache/pre-treatment-proof.log`, `.metal-cache/shared-depth-proof.log`.


## Opt-in motion groundwork

The fixed design makes the motion buffer **moving objects only**: `temporal_render.{h,m}` supplies native-resolution **1x RG16F plus R8 coverage**, after scene MSAA resolve. A covered pixel stores the moving object's full previous-minus-current UV displacement; coverage distinguishes valid zero motion from no object. Coverage clears once per frame; uncovered RG16F values are undefined and ignored. Moving rigid, depth-writing, unblended instances replay once at pixel centres against resolved raw depth, retaining material alpha/discard. Accepted SP/P0/P1 rectangles share the atlas; later views load it. Identical poses and conservative bounds of at most **1/16 pixel per axis** skip replay; near-plane crossings and wheel spin retain it. Queue-owned destructible transforms retain node identity and lifetime epochs. **Camera motion belongs inside the TAA resolve consumer, and later SSR.** Consumers include the source from `temporal_render_camera_msl()` and bind the accepted view's `views[view]` constants: `temporal_consumer_motion` selects covered object motion, otherwise `temporal_camera_motion` reconstructs the static-world vector from resolved depth and the previous view-projection. Cuts seed zero camera motion. There is **no reprojection pass, shader entry point, encode or switch** in the frame. Returning the object atlas requires no motion resolve. No current consumer requests motion; disabled guards enter no temporal work, allocation, bindings, counters or encoding. Jitter, depth/reactivity history and the TAA consumer remain future work. With **BOOT_DIAG**, the objects pass logs a sampled frame/view's drawn instance count (including instanced multiplicity) and isolated GPU ms once per second. Off adds no clocks, counters or completion handlers; unavailable GPU counters report -1 ms.

The fixture includes the shipping shared function inside a mock consumer and compares it with SHA-256-pinned stored-combined camera/object shaders: **24,640/24,640 motion components match exactly**, across pan, body/wheel transforms, occlusion, override, destructibles and covered zero motion. Independent analytic checks and minimum-resolved-depth selection also pass. Stale previous VP in the function, omitted object override and unresolved function depth all fail numerically, alongside seven other controls. It verifies one production objects encoder, frame clearing, disabled diagnostics, instanced counts and deterministic one-second logging. Metal API validation is enabled. The **3840x2160, scene MSAA 4x, six warmups, median N=31** fixture measures only the objects pass, including coverage clearing; the mock consumer and combined reference are outside the timed command buffer. Realistic player + six traffic + two cops: 9 bodies, 36 wheels, 105 parked draws skipped, 19.3646% coverage; **0.180000 ms**. Worst, all 30 moving: 30 bodies, 120 wheels, no skips, 64.5486% coverage; **0.901750 ms**. An alternating paired control that additionally clears RG16F measures **0.239875 / 0.946750 ms**, realistic/worst, so shipping clears only coverage. Reprojection passes: **0**. The two motion attachments total **41.4720 MB** at 4K. Proxy depth uses the same geometry; these counts and declared areas do not establish real mesh cost or appearance. Execution conditions are uncontrolled, and these are not solo game timings. Proof: `.metal-cache/g1c5-motion-proof.txt`; no game runs.
