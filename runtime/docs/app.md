# The app, the F10 menu, restart and problem reports (part 1 of 2)

Part of the runtime documentation; the index and switch lookup hint are in `runtime/README.md`.

## The app (`app.m`, `bundle.sh`)

`runtime/bundle.sh` (after `build.sh`) makes `runtime/NFSMW.app`: `boot` as the executable, an Info.plist (racing-games category, Game Mode, high resolution, game controllers), a generic speedometer icon drawn by `app_icon.m`, and an ad-hoc signature. Double-click it, or `open runtime/NFSMW.app` (`--env BOOT_USERDATA=<scratch>` for test runs; `--args <game folder>` sets the folder without the panel). As an app:

- **Game folder:** asked for with an open panel on the first launch (hold Option at launch, or NFSMW > Change Game Folder…, to choose again) and kept in `USERDATA/app.txt`. A folder is accepted only when its `speed.exe` has the PC v1.3 code the game was translated from: a code fingerprint over the .text/.rdata/.data bytes and PE layout (headers, timestamp, resources and appended data are ignored; a repack with the same code is accepted; `recomp/exe_fingerprint.py`), which `build_all.py` writes into `recomp/out/table.c`; a different region is named in the message. `runtime/boot <folder>` checks the same. X360 extras come from the X360 root Setup records in `roots.txt`.
- **Window:** starts full screen. F10 > Display & performance > **Full screen** selects **Borderless** (default: no Space, instant Cmd-Tab) or **Native** (Cocoa full screen in its own Space, allowing macOS Game Mode). Saved as `display.fullscreen` in `app.txt`; Restart game required; `NFS_FULLSCREEN_MODE=borderless|native` overrides. Both hide the Dock/menu bar. The green button, Window > Zoom, View > Enter Full Screen (Ctrl-Cmd-F), or F10's Window mode row enter the selected mode; View/F10 or Native's green button/Escape return to a resizable window. This state is remembered as `fullscreen`; `NFS_FULLSCREEN=0|1` overrides it at launch. Terminal launches otherwise follow the game's captionless/full-screen choice. Both preserve back-buffer aspect fit, mouse mapping and cursor hiding. Cocoa controls Native's frame; Borderless and widescreen “native” resolution stay below the camera housing (3456x2160 on a 16").
- **Quit:** Cmd-Q, the red button and the Dock all send WM_CLOSE, so the game leaves through its own exit path (`ExitTheGameFlag`, `DeInitializeEverything`, `ExitProcess`); a second Quit while it shuts down quits at once.
- **Focus:** when the window loses focus, held keys and buttons are released and the gamepad reads neutral, and the game is told (WM_ACTIVATEAPP), so it pauses itself as on Windows (it waits in `GetMessageA`, with the guest lock released). `runtime/boot` from a terminal keeps running in the background so scripted runs work; `NFS_PAUSE_INACTIVE=0|1` overrides either.
- **Logs:** `~/Library/Logs/NFSMW-port/NFSMW.log` (the previous run in `NFSMW.previous.log`; Help > Show Logs in Finder). Each running copy has its own log: a copy started while another runs writes `NFSMW-2.log` (a lock file, `NFSMW.lock`, marks the one in use), so it never moves a log that's still being written. Crash reports without `BOOT_DIAG` go to the same folder (`NFSMW-crash.txt`, `NFSMW-2-crash.txt`); a fatal runtime error on the main thread also shows an alert. `BOOT_LOG=<file>` writes elsewhere, `BOOT_LOG=-` keeps stdout. `runtime/boot` keeps printing to the terminal.
- **Defaults:** no diagnostics, and audio output chosen for the device (Audio mode below).
- **Performance overlay** (`overlay.m`): View > Performance Overlay > Off / Compact / Full, Cmd-Option-P cycles; saved as `overlay` in `app.txt` (default off); `NFS_OVERLAY=off|compact|full` overrides. Compact: fps, frame ms p50/p99, sim rate. Full: 4 s graph (frame interval, game-thread CPU, GPU, frame budget), the game thread's busy/sleep/GIL/GPU-wait split, sim ticks per frame with catch-up and repeated frames, GPU ms, draws, background shader compiles, texture uploads, memory (RSS, guest heaps, GPU textures/buffers, HD vinyls/skins), back buffer / window size, aspect, post chain, shadows, antialiasing, audio output and device, controller and rumble motor levels. Its own sublayer at the window's backing scale, filled by the presenter queue; the counters are the always-on per-frame ring stats.log also uses (`perf_frames` in `diag.c`), so its numbers match stats.log. Works in `runtime/boot` too.

## Settings menu: F10 (`portmenu.m`, `settings.c`, `settings_port.c`)

The port's own settings, over the game: **F10** (**Fn-F10** on Mac keyboards, where plain F10 is the system's Mute key and never reaches the app), or the controller's **touchpad click** (DualSense / DualShock 4; pads without a touchpad: View/Back held 0.5 s, or the Guide button if macOS delivers it). The same key or button closes it. Tabs: Picture, World, Cars & cutscenes, Mirror, Display & performance, Audio, Controls, Gameplay (the gameplay options, below), Help. Rows are listed by an explicit `order` key per setting (`settings.h`; ties by id; never by constructor link order), with section headings (World: Lighting and shadows / Surfaces and weather / Detail and textures; Audio: Sound / Xbox 360 sound; Controls: Pad / Rumble / Steering; Gameplay: Career / Changes your save; Help: Performance / Report a problem / Logging). Values say where they come from (**PC** / **X360**, port extras by name); a **⟳** after the value marks a row that needs Restart game (amber "after restart" once a change waits); each row's help is one plain sentence. The performance overlay is one row (Display & performance). **Look preset** (first row of Picture): *Port (recommended)* restores the shipped picture defaults; *Xbox 360 retail* and *PC retail* select the platform picture rows plus the authored colour filter at 100%, Original world lighting, Clip highlights, Banding Off, HDR Off, police glow Off, Standard car reflections, contact shadows and soft smoke Off, chase camera Off, X360 glow footprint and Glow bloom at 100%. PC retail also restores the PC's reduced, squeezed, fog-free mirror without anti-aliasing, original mirror art, fog distance, detail and streaming. Both retail choices disable private later-game car and texture overlays. Audio, device, input and gameplay preferences are preserved, apart from the explicitly visual chase-camera effect. These are the **closest to retail** looks: the port keeps its own bloom bright-pass math, a rendered mirror and some PC world assets. Xbox 360 retail uses the X360 grade data after Restart game; affected startup rows are counted in the status line. Without all X360 assets, it applies available values and says **“partial: your Xbox 360 files are not installed”**; that status also appears whenever the preset row is selected. *My picks* is the fourth choice. Any Picture or preset-owned visual edit auto-saves all values and shows My picks; selecting it restores them after other looks or restarting. This includes Brightness and Anti-aliasing; named presets preserve those two rows. Environment conflicts show My picks without replacing saved picks. Old Custom choices migrate to My picks. The selected choice and row values persist in `app.txt`; old picks remain readable, with expanded picks split across `graphics.my_picks`, `.2` and `.3` to fit the preference value limit. Hidden preset-owned keys `graphics.look_data`, `graphics.look_contact_shadows`, `graphics.look_soft_smoke`, `graphics.look_fog` and `graphics.look_mirror_art` use existing startup switches and add no F10 rows. Private builds also keep hidden reflection and later-texture overrides. Offline tests: `runtime/settings_look_test.c`, `runtime/builtin_features_test.py`, `tests/setup/test_menu_x360.py`. **Anti-aliasing** (Picture, second row) is the game's own Video options > Antialiasing: the row reads and writes `g_FSAALevel` (no copy, so both always agree), saves it in registry.txt and queues the device Reset as the options screen's Accept does; test `runtime/aa_setting_test.c`. Raindrops and Rain ripples are in World; Scenery lights in Lighting and shadows; Reverb and Extra EA Trax in Sound; Control type in Steering. Works in `NFSMW.app` and `runtime/boot`.

- **Keyboard:** Up/Down choose, Left/Right change, Enter or Space select (toggle, cycle, run, edit a text field), Tab / Shift-Tab or Q / E category, Backspace back to the default, PgUp, PgDn, Home, End, Esc or F10 close. **Mouse:** hover, click a tab, click a value to change it (on its left arrow: back one), drag a slider, scroll the list; a click outside the panel closes. **Controller:** D-pad or left stick choose / change, ✕ select, ○ back (closes), L1/R1 category, △ default (Xbox: A, B, LB/RB, Y). Options stays the game's pause. The help line at the bottom follows the device last used.
- **Controller shortcut** (Controls > "Controller: open this menu", `NFS_MENU_BUTTON=touchpad|home|l3r3|view`): touchpad click (default), PS/Guide button, L3+R3 held 0.4 s, or Create/View held 0.5 s. For a held Create/View the button is held back from the game until it's clearly a tap (released within 0.5 s: the game gets it then, e.g. reset car) or a hold (the menu). PS/Guide: the runtime sets `preferredSystemGestureState = disabled` on the Home button (GameController, macOS 11+) so macOS doesn't take the press for Launchpad / its game overlay while the game is frontmost; whether a given macOS version still keeps it is logged (`pad: Home button delivered to the app`, BOOT_DIAG). The game doesn't use the touchpad (it isn't one of its 12 DirectInput buttons), so the touchpad shouldn't be bound to anything else by default.
- **While open the game gets no input:** keys, characters, mouse and the pad go to the menu (keys and buttons held when it opens are released to the game first; ones held when it closes stay away from the game until released), and the system arrow cursor shows over the game. **In a race (game-flow 6) the game is frozen:** `pacing.c`'s AdvanceRealTime hook holds the real-time clock as the probe hold does, so `RealTimer` (the Scheduler's target timer, `Scheduler::GetTargetTimer` 006277D0) stops: no sim ticks, so sim time, the race clock, AI and pursuit timers stand still while frames keep rendering (live graphics changes show on the frozen scene); the game's own PauseMenu sound state (`SetSoundControlState(true, 1)` 004B9080) pauses its sound effects unless its pause menu already did. Closing resumes from the same tick, at the normal rate. In the front end nothing is frozen (input only). The game's own window procedure (FUN_006db6c0) doesn't handle F10 (it handles End, Home, Left, Right, F12 and Ctrl), so the menu takes F10 from it; F10 can't be bound in Options > Controls while the port runs.
- **What it holds:** the switches that make sense to users, live where the code allows: window mode, performance overlay, post-processing, tone curve, car glass, raindrops, mirror brightness/detail, audio output, button layout and rumble. Road reflection, mirror resolution/anti-aliasing and shadow fit apply through the game's device reset at the next frame. World streaming is live when launched with Ahead; car paint and rain ripples are live when launched with X360. The remaining settings carry a ⟳ (restart via Display & performance > Restart game); see the lifetime audit below. A switch set in the environment wins: the row shows "set by NFS_X=..." and can't be changed.
- **Saved** in `USERDATA/app.txt` (the same file as the window mode and the Audio/Controller/View menus; those keep their keys, so both stay in step), only when changed. At start-up a saved value that differs from its default is exported to its `NFS_*` switch (unless the environment set it), so the code that reads its switch once keeps working unchanged.
- **Adding a setting** (from your own file): a static `Setting` with id, category, label, help, type (`SET_TOGGLE`, `SET_CHOICE`, `SET_SLIDER`, `SET_TEXT`, `SET_ACTION`, `SET_INFO`, `SET_HEADING`), choices and their switch values, default, `env`, `restart` or an `apply(value)` for live changes, registered with `settings_add()` from a constructor; read it with `settings_get(id)`. The header (`settings.h`) has a worked example.
- **Drawing:** a Core Animation layer over the game's at the window's backing scale (sharp at any game resolution), its bitmap drawn with CoreText at most once a frame and only when something changed (once a second for the live readouts; ~10-15 ms at 2x on the game thread, only while open), plus a dim layer; nothing is drawn while closed. With `BOOT_DIAG_SHOTS` and the menu open, `menu_NNNNN.png` is the panel with alpha (the frame PNG has the game without it). `BOOT_DIAG` logs `menu:` lines (open/close, tab, every change, the panel's size and time).
- **Tests:** `BOOT_KEYS` keys `F10`, `TAB`, `Q`, `E`, arrows, `RETURN`, `BACK`, letters typed into a text field; steps `race:N` (N ticks after the race state began), `pad:0x2000` (touchpad click, with `BOOT_PAD=sim:`; bit 12 is PS/Guide) and `pad:MASK:N` (held N ticks, e.g. `pad:0x300:40` for L3+R3).

**Help** in the menu: the performance overlay modes, a live readout (fps, p99 frame time, GPU time over the last second; the audio output and device), **Report a problem** (what's wrong: Audio / Graphics / Controls / Gameplay / Crash-freeze / Other; an optional note typed on the keyboard; Save report), Show reports / logs in Finder, and **Full diagnostic logging** (from the next launch: `BOOT_DIAG=<userdata>/logs/<YYYYMMDD-HHMMSS>`; turn it off afterwards).


**Guide** is the first action in F10 > Help. It reads the bundled `Contents/Resources/Guide.md` without leaving the menu.
A hidden switch `NFS_GUIDE_BUTTON=view_r3|off` (default `off`, no F10 row) keeps the old direct shortcut: hold Create / View
first, then press R3 and hold both for 350 ms. Short Create / View taps reach the game on release;
R3 while Create / View is held belongs to the shortcut. The ordinary Create / View menu hold waits while R3 is held.
D-pad / left stick or arrows scroll by line, L1/R1 (LB/RB) or PgUp/PgDn by page; Home/End reach the ends, and the wheel scrolls.
Circle/B, Esc, Backspace or Back to Help returns to Help; F10 closes everything. Pause, sound and input ownership stay with F10.
The document has 20-point text, 28-point leading, a clipped viewport, a scrollbar and a percentage;
it uses the menu's own scale. Missing, empty or invalid UTF-8 documents show an error with Back available.
Headings, paragraphs, bullets and bold are supported; other markup stays literal.
**What to test** appears after Guide only when `Contents/Resources/Testing.md` exists. It uses the same viewer and is reached
through F10 only. `bundle.sh` optionally copies `NFS_TESTING_MD` (relative paths are based at `runtime/`; default `docs/testing.md`);
an absent checklist is fine. Public builds omit the checklist even when the source or override exists.

### Live changes and Restart game

**F10 > Display & performance > Restart game** confirms inside the menu (works with a pad): the first press shows "Press again within 4 s to restart; race progress since the last save is lost.", a second press within 4 s restarts. **Quit game** (row above it) closes the game the same way (two presses within 4 s, settings saved, then the Mac's Quit path), so a pad player never needs the keyboard.
Cancel is the default button. On confirmation, `app.m:138` writes, flushes and fsyncs the current settings to a
staging file and atomically renames it to `app.txt`; a save error cancels the restart. Quit then follows the existing
NSApp delegate -> `user32_request_close` (`user32.m:502`, rumble/lightbar off, WM_CLOSE) -> game shutdown ->
`ExitProcess(0)` (`boot.c:788`) path. The existing guest CloseHandle path fsyncs and atomically installs completed
saves (`boot.c:510`); the host audio exit handler closes both live and parked outputs (`host/audio/dsound_host.cpp:757`).
This does not save unsaved race progress. Fatal exit, TerminateProcess and forced Quit do not arm a replacement.

The restart handler is registered before the other runtime exit handlers (`app.m:93`), so their cleanup runs first.
It spawns the same executable as a small waiter; `EVFILT_PROC/NOTE_EXIT` waits for the old process to exit before
`execve` starts the replacement (`app.m:48`, `app.m:70`). There is no overlapping game instance. The launch arguments,
working directory and original launch environment are preserved. The snapshot precedes `settings_init` and
`report_init`: internally exported **old saved settings** and generated diagnostic paths must not override the
new `app.txt`. Explicit environment overrides remain overrides. Direct execution of a bundle's own
`Contents/MacOS/NFSMW` keeps that same bundle; terminal launches re-execute `runtime/boot`.

With **either `BOOT_DEADLINE` or `BOOT_BACKGROUND` present**, the item reports "Restart disabled in unattended
runs" and does not show a modal, quit, or spawn. Both preparation and the exit handler also check this restriction.
The waiter repeats the guard check. Spawn/exec failures are reported on stderr; it never launches a fallback copy.

The lifetime audit below distinguishes live settings (including conditional world streaming) from restart-only resources.
"Restart only" means the current port retains boot-loaded guest resources; replacing them safely would require a
larger reload path. No race/front-end load was found that reconstructs the entire affected resource set.
