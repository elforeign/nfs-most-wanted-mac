- Scenery lights (R20, `auxlights.c` / `materials.m` / `render.m`; **PC default, appearance verification pending**): `NFS_AUX_LIGHTS=pc|x360`, F10 Graphics > Scenery lights (live). No mirror/shadow/debug, car, grass, glass or particle auxiliary pass. `NFS_TEST_AUX_SIGNATURE=1` replaces only a positive, normally depth-tested auxiliary result with cyan. - Rain ripples on wet roads (material-shader layer, `materials.m` payload 2; **X360 by default**, `NFS_RAIN_RIPPLES=pc` keeps the PC shaders untouched; F10 Graphics > Rain ripples on wet roads, live in a run started with the default): the X360 `wetroad` PS 09c17c18 rain term on the PC `worldreflect` shaders. The translations are patched, not replaced: VS t0 (no shadows) and t1 (shadow levels 1-5) also write oT2.zw = the world position X/Y scaled to ripple tiles (top-down); PS t0-t5 sample the ripple frame there and at a larger scale (s = sum), offset the reflection lookup by the ripple sample scaled by R, add a glint term and darken the reflection with R, all inside the sampled reflection colour, so every other PC instruction (lighting, shadows, 2 x specmap x diffuse alpha x wetness, fog) is kept and R = 0 gives the PC output. R = the current view's Rain +0x28C (rain intensity 0..1; the view as FUN_006d71f0 picks it: *(0x00919648 + id x 0x70)); frame = (int)(rate x fmod(t, 16 / rate)) (X360 Function_8244F928, 16 frames; the rate is `X360E_RIPPLE_FPS`) with t = the sim time (Sim::GetTime 009885D8: deterministic per sim tick, so the reference frames repeat; the X360 uses its 1/4000 s ticker, [I] real time). The 16 `RAINSPLASH00-15` frames (128x128 DXT1, X360 `GLOBAL/GLOBALB.BUN` only) are read at start-up through the X360-only texture reader (`x360_texture_rgba`), decoded and given box-filtered mips as one 2D array texture at fragment texture(15) (`render.m` `ripple_texture`); without them R is 0 (PC look). Visible only where the PC draws the reflection (road reflections >= 2, wetness > 0.01) and it rains: 15.1.1 at the start line rains ~0.8 until ~sim 13 s, wet ~0.9 by 10 s. BOOT_DIAG: `materials:` lines for each patched shader and the rain/frame every 20000 draws. Probe `ripples`: the patched PS outputs magenta where R > 0 and wetness (SpecularColour.w) > 0.01. Capture: `run_shots/rain_ripples_pc_vs_x360.jpg` (stationary at sim 8 s; in daylight the visible change is mostly the dimmer, broken-up reflection; the rings themselves are faint, as the X360 maths makes them).

- Soft smoke (private port extra, default **On**, built in, no F10 row;                                                        ): hidden `NFS_SOFT_SMOKE=off` disables it for A/B; unset/anything else enables it. Obsolete `graphics.soft_smoke` profile values are ignored. Native single-player post records supported main-view particle draws, preserves particle/rain/additive order, and replays them into a **single-sample premultiplied layer** after the existing scene/depth resolve. Only alpha-blended smoke/dust receives the 0.6-m depth fade (`NFS_SOFT_SMOKE_RANGE=0.05..4`); rain/additive shading and depth rejection remain. Nearest depth resolves on the existing opaque store; there is no separate depth snapshot or MSAA scene split. Occluded fragments exit before shadow shading. With contact shadows On, composition merges into the existing AO multiply; AO Off uses a standalone composite. PC post/split/unsupported states retain the early path. Off retains the original shader. [New labelled controls](../run_shots/soft_smoke_late_same_input.jpg) explicitly use 1x particles over 4x opaque geometry, not original 4x-particle frames. Same contact metric: frame 423 road/cars 13,602/23,079 -> 10,104/18,355 (25.72%/20.47% fewer); frame 564 33,742/24,301 -> 32,160/15,380 (4.69%/36.71%). Broken fade fails. `soft_smoke_test.py --cost <diag>` checks held-frame pairs and no MSAA split. Final non-solo 9-pair delta median -1.090 ms, range -4.399..+4.670 ms: too noisy to establish the requested +0.3-ms bound.

- Lens raindrops (`x360_post.m` drives, `render_x360_raindrops` in `render_post.m` draws; with the X360 chain only): PC draws the drops on the lens (FUN_006D4620, `rain_drop.efx`, 16x16 `RAINDROPPC`) before the visual treatment, into the screen copy it reads, so the X360 chain speed-blurred, depth-of-fielded and graded them. The X360 draws them after its composite (Function_82448000) with the particles effect's `onscreen_distort` (PS 09beae34). The drop pass is now deferred (hook 006D4620, only when the X360 composite will run that frame) and replayed after `render_x360_post`: `NFS_RAINDROPS=x360` (default) as the X360 draws them: quads of r = 0.05 x size, r/aspect wide (round on any screen), refracting the composited frame through the 32x32 displacement `ONSCREENRAINDROP`, shaded and masked by the 128x32 4-variant atlas `ONSCREENRAINDROPALPHA` (both loaded from `GLOBAL/GLOBALB.BUN` at start-up through the X360-only texture loader; BOOT_DIAG writes them as `x360_texture_0A49165B.png` / `0A6F8AA1.png`); `=pc` the game's own pass after the composite (PC look, 4:3 drops); `=pc_before` the game's pass where PC draws it (the port before 2026-10-20, for comparisons). Without the X360 textures `x360` uses `pc`. `NFS_POSTFX=pc` leaves the PC order. Drops: the Rain object at eViews[1] + 0x68 (009196B8), count at +0, record i at +i*0x1C (+4 x, +8 y, +0xC/+0x10 life, +0x14 size, +0x1C variant); 20 in view modes < 3 (15.1.1's default chase camera), 10 from 3 up, none in tunnels or while the rain intensity (+0x28C) is 0. **When it rains:** map rain zones at the car's position (15.1.1 rains from its start, intensity ~0.8; `g_RainEnable` must be on, as the first-run defaults have it), NIS rain events, script overrides. The drop pass's library and pipeline (per target sample count), the two drop textures' upload and the 16-frame ripple array are made by the first X360 composite (`render_x360_raindrops_warm`), i.e. during loading/front end, not at the first rain frame (a 119 ms hitch in a user session); BOOT_DIAG logs each creation's ms (`render: raindrops library/pipeline/textures`, `rain ripple array`), the frame counters' pipeline count includes them, and `NFS_NO_RAINWARM=1` (test only) restores the lazy first-use creation for A/B. `NFS_TEST_RAIN=<0..1>` (test only) writes `rainOverrideIntensity` (009B0A48, SetOverRideRainIntensity 0073C970, read by FUN_007539D0 before the zones) every frame, so it rains anywhere. BOOT_DIAG logs `raindrops:` (drop count and intensity when they change, the first pass). Cost (15.1.1, 3440x2160, 4x MSAA, forced rain, 20 drops; 2026-10-20, runs overlapped other games on the machine, so within noise): x360 busy 4.05 ms / GPU 5.11 ms per frame against pc_before 4.18 / 5.68 (both 120 fps). Capture: `run_shots/raindrops_x360_order_look.jpg`. Probe: `raindrops` (the pass draws the drops' cover magenta).
- **Bloom on bright areas** (`NFS_BLOOM_SURFACES=glow|halo|natural`, F10 Graphics > Bloom on bright areas, default `natural` (`settings_port.c:106`                                                                                              ): `natural` conserves energy: scene + 0.20 x (blur(B) - B) at Bloom 100 %, spreading near-white light without lifting a broad bright surface or adding a ring (`x360_post.m:212–217`). The earlier Glow/Halo comparison follows: the maskless bright pass lets any surface above the knee bloom, and the bloom chain lifts an area bigger than its kernel by ~6.2x its bright-pass excess (5x5 gauss and downsample sum 1, the Bloom kernels ~1.96 each, x bloom scale 1.6), so sun-lit snow caps, smoke/spray and lit road strips clip flat, more so as the adapted luminance drops. `halo` subtracts that own lift (the 5x5-blurred bright pass x the kernels' gain, `x_bloom_gain` in `render_post.m`) in the composite, so such areas keep their texture and only the light spilling past their edges is added. Same held frames (15.1.1, 3440x2160; glow / halo / bloom 0): snow cap 30.2 / 0.25 / 0 % clipped, road spray 19.1 / 0.36 / 0.36 %, whole frame at sim 20 s (adapted 0.22) 0.84 / 0 / 0 %. `BOOT_DIAG_LOOK_AB` variants `glow` and `halo`.
